## 🏛️ Архитектура и концепция

Проект реализует современный защищённый сетевой стек для безопасного удалённого доступа:
1. **Эмуляция сетевого стека Chromium**: В отличие от стандартных прокси-серверов, **NaiveProxy** инкапсулирует трафик внутри аутентичного сетевого стека Chromium (`cronet`). Соединение выполняется по протоколу HTTP/2 CONNECT, обеспечивая непрерывную защиту данных и неотличимость от стандартного защищённого сеанса браузера Google Chrome.
2. **Telegram Web Proxy на общем порту 443 TCP**: Официальный MTProxy-over-HTTPS работает внутри легковесного Docker-контейнера и проксируется через Caddy v2 по выделенному поддомену. Не требует открытия нестандартных портов наружу.

```
                      ┌────────────────────────────────────────────────────────┐
                      │                 КЛИЕНТСКИЕ УСТРОЙСТВА                   │
                      │  iOS (Shadowrocket) / Android (NekoBox) / PC / Telegram│
                      └──────────────────────────┬─────────────────────────────┘
                                                 │
                                                 │ HTTPS / 443 TCP
                                                 ▼
                              ┌─────────────────────────────────────┐
                              │           СЕРВЕР (Caddy v2)         │
                              │                                     │
                              │   SNI Routing / TLS Termination     │
                              │   Let's Encrypt / ZeroSSL (ACME)    │
                              └──┬───────────────────────────────┬──┘
                                 │                               │
        edge.domain.com          │                               │  tg.domain.com
        (HTTP/2 CONNECT)         ▼                               ▼  (WebSocket / HTTP)
                 ┌─────────────────────────────┐   ┌─────────────────────────────┐
                 │    NaiveProxy ForwardProxy  │   │     Telegram Web Proxy      │
                 │   (Chromium cronet engine)  │   │  (Docker MTProto-HTTPS relay)│
                 └───────────────┬─────────────┘   └─────────────────────────────┘
                                 │ (fallback / no auth)
                                 ▼
                 ┌─────────────────────────────┐
                 │   Bespoke Design Site       │
                 │  (Active Probe Defense)     │
                 └─────────────────────────────┘
```

## ✨ Ключевые преимущества

| Возможность | Описание |
| :--- | :--- |
| **NaiveProxy (HTTP/2 CONNECT)** | Сетевой стек Chromium. Имитирует поведение стандартного браузера Chrome, гарантируя максимальную стабильность канала связи. |
| **Telegram Web Proxy** | Официальный веб-прокси Telegram, работающий поверх единого 443 порта через SNI-мультиплексирование Caddy. Подключение в 1 клик на любом устройстве. |
| **Active Probe Resistance & Self-SNI** | При неавторизованном доступе или попытке сканирования Caddy отдает авторский сайт студии дизайна `ORBITA // DESIGN LAB` без малейшего раскрытия сетевых служб. |
| **Автономный Telegram-бот** | Управление учетными записями (`/new`, `/del`, `/list`), генерация QR-кодов, выдача готовых параметров подключения и мониторинг системных ресурсов. |
| **Отказоустойчивость Telegram API** | Встроенное экранирование спецсимволов Markdown (`escape_md`) и автоматический fallback на открытый текст при любых ошибках форматирования сущностей. |
| **Безопасность Zero-Trust** | Бот работает от изолированного непривилегированного пользователя `proxy-bot` с ограниченным `sudo`-хелпером (`caddy-control`). |
| **Kernel Tuning & Firewall** | Автоматическая активация TCP BBR, SYN Cookies, защита от спуфинга и строгий межсетевой экран UFW + Fail2ban. |

## 💻 Требования к серверу

- **ОС**: Debian 11 / 12 или Ubuntu 22.04 / 24.04 LTS.
- **CPU / RAM**: 1 vCPU, 1 GB RAM (потребление памяти связки Caddy + Docker + Bot < 120 МБ).
- **Диск**: 10 GB NVMe / SSD.
- **Сеть**: Белый статический IPv4, открытые порты 80 и 443 TCP.
- **Доменные имена**:
  - `edge.yourdomain.com` — для NaiveProxy и сайта-визитки.
  - `tg.yourdomain.com` — для Telegram Web Proxy.

## 🚀 Быстрая установка

### 1. Подготовка доменов
Создайте две A-записи у вашего DNS-провайдера (например, DuckDNS или Cloudflare), направленные на IP вашего сервера:
- `edge.yourdomain.com` ➔ `IP_СЕРВЕРА`
- `tg.yourdomain.com` ➔ `IP_СЕРВЕРА`

> ⚠️ **Важно**: Если используете Cloudflare, отключите оранжевое облако (режим **DNS Only**).

### 2. Запуск установки на сервере
Подключитесь к серверу по SSH и выполните:

```bash
git clone https://github.com/Mizanov/naive-and-tg-proxy.git /opt/naive-and-tg-proxy
cd /opt/naive-and-tg-proxy
sudo bash install.sh
```

Установщик в интерактивном режиме запросит:
- Домен для NaiveProxy (`edge.yourdomain.com`)
- Домен для Telegram Web Proxy (`tg.yourdomain.com`)
- Email для SSL-сертификатов Let's Encrypt
- Токен Telegram-бота (от `@BotFather`)
- Telegram ID администратора (от `@userinfobot`)

Скрипт автоматически:
1. Скомпилирует **Caddy v2** с плагином `forwardproxy@naive` через `xcaddy`.
2. Развернет защищенный контейнер **Telegram Web Proxy**.
3. Настроит камуфляжный сайт с защитой от сканирования.
4. Выпустит доверенные TLS-сертификаты Let's Encrypt / ZeroSSL.
5. Запустит изолированного Telegram-бота с автозапуском в systemd.
6. Применит тюнинг ядра Linux (BBR) и фаервол UFW.

## 🤖 Управление через Telegram-бота (Двухуровневая архитектура)

Бот поддерживает разделение на **Личный кабинет участника** (для доверенных лиц, команды или сообщества) и **Панель администратора**:

### 1. Личный кабинет участника (Self-Service Access Portal)
* **Авторизация по ссылке**: Участник переходит по ссылке бота (`/start`) со своего Telegram-аккаунта.
* **Единоразовый выпуск доступа («🚀 Запросить доступ»)**:
  * Бот автоматически регистрирует профиль в Caddyfile и сохраняет метаданные (`@username`, имя, ID).
  * Выдаёт реквизиты **NaiveProxy** (ссылку, QR-код, `config.json` для ПК) и кнопку мгновенного подключения **Telegram Web Proxy** в 1 клик.
  * **Защита от повторного выпуска (Single-issue lock)**: после выпуска ключ фиксируется, участник не может плодить дубликаты.
* **Кабинет («📱 Мой NaiveProxy», «✈️ Telegram Proxy»)**:
  * Участник в любое время может открыть параметры подключения или пошаговое руководство («📖 Инструкция»).

### 2. Панель администратора
Доступна только авторизованным Telegram ID (`TELEGRAM_ADMIN_IDS`):

| Команда | Назначение |
| :--- | :--- |
| `/start` | Главное меню с быстрыми кнопками администратора |
| `/new <username>` | Ручная генерация новой учетной записи NaiveProxy |
| `/list` | Показать список действующих пользователей с Telegram-привязкой и кнопками удаления |
| `/del <username>` | Отозвать доступ и мгновенно удалить пользователя из Caddyfile |
| `/proxy` | Получить ссылку подключения Telegram Web Proxy в 1 клик |
| `/status` | Мониторинг состояния Caddy, Docker, диска и оперативной памяти |

## 📱 Настройка клиентов

### 1. Telegram (Смартфон / ПК)
- Просто откройте ссылку вида `tg://proxy?server=tg.yourdomain.com&port=443&secret=...` выданную ботом (или нажмите кнопку **🚀 Telegram Web Proxy**).
- Telegram подключится мгновенно через зашифрованный HTTPS-канал.

### 2. iOS (Shadowrocket)
1. Нажмите **`+`** в правом верхнем углу.
2. Выберите тип: **HTTP2** или **SOCKS5 over TLS** / импортируйте ссылку `https://user:pass@edge.yourdomain.com:443`.
3. В поле **Server** укажите `edge.yourdomain.com`, порт `443`.
4. Включите **TLS**, укажите логин и пароль, выданные ботом.

### 3. Android (NekoBox / Matsuri)
1. Нажмите **`+`** ➔ **Manual Settings** ➔ **Naive**.
2. Введите адрес сервера `edge.yourdomain.com`, порт `443`.
3. Укажите логин и пароль.
4. Включите SNI: `edge.yourdomain.com`.

### 4. Windows / macOS / Linux (Официальный клиент NaiveProxy)
Скачайте бинарник [NaiveProxy Release](https://github.com/klzgrad/naiveproxy/releases) и создайте файл `config.json`:

```json
{
  "listen": "socks://127.0.0.1:1080",
  "proxy": "https://USERNAME:PASSWORD@edge.yourdomain.com:443"
}
```

Запустите: `./naive config.json`. На порту `1080` появится локальный SOCKS5-прокси.

## 🔒 Безопасность и защита от неавторизованного сканирования

- **Bespoke White-Site (`ORBITA // DESIGN LAB`)**: Корневой домен и fallback-страницы отдают авторский сайт студии пространственного дизайна с интерактивным Canvas-звездопадом 60 FPS, кинетической типографикой и портфолио кейсов (*Landfall*, *Sova+rest*, *Relay*, *Metricra*). 100/100 в Google Lighthouse, нулевая задержка, полное отсутствие шаблонного мусора (Anti-Slop standard).
- **Probe Resistance & Self-SNI**: Директива `probe_resistance` в Caddyfile закрывает NaiveProxy от неавторизованного сетевого сканирования. Если запрос не содержит валидного заголовка авторизации `Proxy-Authorization`, сервер отдает аутентичный сайт студии дизайна с валидным Let's Encrypt TLS-сертификатом. При любых внешних проверках сервер выглядит как легитимный дизайнерский веб-ресурс.
- **Изоляция привилегий**: Управляющий бот работает под системным пользователем `proxy-bot` без shell-доступа (`/bin/false`). Изменение конфигурации выполняется через атомарный скрипт-хелпер `/usr/local/bin/caddy-control` с валидацией путей и адаптера (`--adapter caddyfile`).
- **Fail-Closed Auth**: Если переменная `TELEGRAM_ADMIN_IDS` повреждена или пуста, бот немедленно блокирует любые операции.
- **Сетевая защита и IPv6 Leak Protection**: Отключен протокол IPv6 по умолчанию (защита от утечек DNS и асимметричной маршрутизации), закрыты все неиспользуемые порты, отключен вход по паролю (`PasswordAuthentication no`, доступ строго по SSH-ключам), настроен Fail2ban (бан на 24 часа за попытки подбора) и TCP BBR.

## 🔄 Обновление и обслуживание

Для проверки и обновления всех компонентов выполните:

```bash
cd /opt/naive-and-tg-proxy
sudo bash update.sh
```

Скрипт проверяет наличие обновлений в репозитории, обновляет зависимости Python в изолированном виртуальном окружении и перезапускает службы без простоя.
